## What the numbers mean

v3 lifts the demo trade count from 1 (v2) to 9, because HVB is now defined by
volume rather than an RSI-travel threshold. On the demo feed the volume is
synthetic, so this is a code check only.

v2 keeps only 1 of the 55 raw setups on this demo window, because the demo feed
is mean-reverting noise: most HVB breaks there are counter-trend or happen in
chop, which is exactly what v2 rejects. **The trade count is the story here, not
the win rate** — a 100% win rate on one trade is meaningless, and the report says
so.

Real exchange data trends, so the filter should keep a much larger share. Run it
yourself:

```bash
# real Binance data, fails loudly if the exchange is unreachable
python scripts/winrate.py --symbol BTCUSDT --days 30 --strategy tdi_shift_v1 --real-only
python scripts/winrate.py --symbol BTCUSDT --days 30 --strategy tdi_shift_v2 --real-only

# same, but a more permissive preset
python scripts/winrate.py --symbol BTCUSDT --days 30 --params '{"filter_mode": "balanced"}' --real-only
```

Compare `Trades:` and `Overall win rate:` between v1 and v2. What matters is
whether v2 keeps the trades that were aligned with structure and drops the
wreckage — not whether the number happens to be bigger.
