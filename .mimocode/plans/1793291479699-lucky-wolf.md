# Plan: How to Use the Signal Lab App

## Overview
Signal Lab is a crypto trading signal application built on FastAPI, a web UI, and SQLite. It evaluates historical (replay) or real-time (live MEXC futures) kline data using a validated machine learning model with a 1:4 reward-to-risk ratio (target 8 ATR, stop 2 ATR, 1h, probability threshold p ≥ 0.35).

## Prerequisites & Installation
1. **Python 3.11+** installed.
2. **Setup virtual environment & install dependencies**:
   ```bash
   cd D:\Business_AGENTS\crypto_signal_app\signal-lab
   python -m venv ..\.venv
   ..\.venv\Scripts\pip install -r requirements.txt
   ```
3. **Build the dataset** (downloads ~700 MB BTC/ETH 2017-2026 archive):
   ```bash
   ..\.venv\Scripts\python tools\build_dataset.py
   ```

## Running the App
Choose one of two modes:

### Mode A: Replay Mode (Simulated historical run)
Runs a historical replay through 2024–2026 data at adjustable speed:
```bash
..\.venv\Scripts\python app\server.py --replay --loop --speed 150 --port 8811
```
Open **http://localhost:8811** in your browser.

### Mode B: Live Mode (Real-time MEXC futures)
Polls real-time kline data from MEXC futures:
```bash
..\.venv\Scripts\python app\server.py --live --port 8811
```

## How to Use the Web Interface (4 Tabs)
1. **Signals**: The live signal tape. Shows time, symbol, timeframe, band probability, entry/stop/target prices, bars held, outcome, and R-multiple.
2. **Measured Accuracy**: Explains the 1:4 reward:risk geometry, accuracy breakdown, and confidence intervals across walk-forward periods.
3. **The 100% Club**: Details the 480 historical in-sample rules that never lost and their out-of-sample performance.
4. **Method & Limits**: Documents data splits, features, and explicit caveats/limitations.

## Verification / Health Checks (No Browser Needed)
- Health API: `curl -s localhost:8811/api/health`
- Stats API: `curl -s localhost:8811/api/state`

## Troubleshooting: Why No Data or Signals Show Up
1. **Dataset Not Built**: If `tools/build_dataset.py` was not run, the historical `.npy` files in `signal-lab/data/` are missing, causing replay mode to fail or show empty state. Run `..\.venv\Scripts\python tools\build_dataset.py`.
2. **Replay Speed Too Slow / Warmup Period**: Replay starts at `2024-01-01` with a 700-bar warmup. At low speeds (e.g. `--speed 25`), it takes time to reach active signal periods, and signals fire sparsely (~0.15 times per symbol per day). Use a higher speed: `--speed 150` or `--speed 300`.
3. **Live Mode Signal Scarcity**: When running in `--live` mode, you do **not** need the historical dataset (`build_dataset.py` is only for replay mode). However, live mode starts fresh and polls MEXC futures every 45 seconds. The signal model has a high probability threshold ($p \ge 0.35$ for 1h candles), meaning signals fire very sparsely (averaging about 0.15 times per symbol per day). If you just started live mode, **it is completely normal for the signal tape to be empty for hours** until a valid setup occurs in the live market. You can check `/api/health` and `/api/state` to confirm streams are connected and polling successfully.
4. **Server Errors**: Check the terminal running `server.py` for Python tracebacks (e.g., missing dependencies or database locks).
